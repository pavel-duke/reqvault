# Формат workspace v1

Формат v1 — стабильный файловый контракт ReqVault. Он рассчитан на хранение в Git, ручное редактирование и использование одной папки в desktop-приложении и CLI.

## Гарантии совместимости

- ReqVault 1.x читает и записывает `format_version: 1`.
- Новые необязательные поля в 1.x получают безопасные значения по умолчанию. Старые клиенты могут их не знать, поэтому перед возвратом на старую версию лучше сделать commit.
- Изменение смысла существующего поля или удаление поля требует нового `format_version`.
- Перед миграцией ReqVault показывает список файлов и создаёт копию в `.reqvault/backups/`.
- Неизвестная более новая версия формата не открывается для записи.
- Секреты и локальная история не являются частью формата и не попадают в bundle.

Workspace из релизов 0.1–0.9 использовали ту же модель данных. Для ранних файлов без явного номера миграция добавляет `format_version: 1`, не меняя остальные значения. Этот путь проверяется отдельным тестом для каждого прежнего релиза.

## Структура

```text
my-api/
├── reqvault.yaml
├── environments/
│   ├── local.yaml
│   └── staging.yaml
├── requests/
│   ├── users/
│   │   └── get-user.yaml
│   └── system/
│       └── health.yaml
└── fixtures/
```

`reqvault.yaml` хранит UUID, название и правила Production Guard. В `environments` находятся только несекретные переменные. Запросы группируются каталогами внутри `requests`.

## Переменные и секреты

- `{{BASE_URL}}` берётся из выбранного окружения.
- `{{secret:API_TOKEN}}` разрешается через Secret Vault непосредственно перед отправкой.
- Пароли proxy, OAuth, Basic/Digest Auth и ключи AWS можно сохранять только как ссылки `{{secret:NAME}}`.

Файл workspace остаётся переносимым, а секретное значение не передаётся во frontend и не записывается в YAML.

## Правила безопасного редактирования

1. Не меняйте UUID существующего workspace.
2. Используйте относительные пути для fixture, multipart и сертификатов, если проект должен работать на разных машинах.
3. Не добавляйте `.reqvault/` в Git: там находятся резервные копии и локальные служебные данные.
4. После ручного редактирования откройте «Диагностику» и устраните ошибки до запуска коллекции.

Актуальный пример находится в [`examples/sample-workspace`](../examples/sample-workspace).
