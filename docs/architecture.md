# Архитектура ReqVault

ReqVault — desktop-приложение Tauri 2. Интерфейс работает в системном WebView, а операции с файлами, сетью и секретами выполняет Rust-часть через ограниченный набор Tauri-команд.

```text
React + TypeScript
  │ invoke(command)
  ▼
Tauri commands
  ├─ workspace ── YAML-файлы в выбранной папке
  ├─ http ─────── reqwest + rustls
  ├─ oauth ────── PKCE, callback и token exchange
  ├─ importer ─── Postman, OpenAPI и cURL
  ├─ guard ─────── правила отправки workspace
  ├─ history ──── локальные очищенные ответы
  ├─ runner ───── assertions и запуск коллекций
  ├─ secrets ──── хранилище учётных данных ОС
  └─ security ─── анализ запроса и безопасный cURL
```

## Frontend

Код находится в `src/`.

- `App.tsx` хранит состояние открытого workspace, выбранного запроса, ответа и темы.
- `api.ts` — типизированные вызовы Rust-команд.
- `components/` — редактор, боковая панель, ответы, окружения, секреты и Security Lens.
- `types.ts` повторяет сериализуемые структуры Rust.

Frontend не читает workspace напрямую и не получает сохранённые значения секретов. Разрешения Tauri дают окну только выбор папки и запись текста в буфер обмена.

## Rust

Код находится в `src-tauri/src/`.

- `commands/` — тонкий IPC-слой без бизнес-логики;
- `workspace/` — создание, чтение и безопасная запись YAML внутри workspace;
- `http/` — проверка данных, подстановка переменных и секретов, отправка запроса;
- `oauth/` — OAuth endpoints, PKCE, локальный callback и запись token в системное хранилище;
- `importer/` — преобразование Postman/OpenAPI в модели ReqVault без переноса открытых credential;
- `guard/` — проверка HTTPS, хоста, метода и секретов в URL перед отправкой;
- `history/` — opt-in история очищенных ответов вне workspace;
- `runner/` — последовательное выполнение запросов и проверка ответов;
- `cli/` — разбор аргументов, консольный вывод и JSON-отчёт;
- `secrets/` — работа с Windows Credential Manager, macOS Keychain или Linux Secret Service;
- `security/` — Security Lens и генерация cURL;
- `variables/` — разбор `{{NAME}}` и `{{secret:NAME}}`;
- `redaction/` — маскирование чувствительных заголовков и известных значений;
- `models/` — общий формат данных.

## Поток отправки запроса

1. Frontend отправляет структуру запроса, выбранное окружение, путь и UUID workspace в Rust.
2. Rust загружает Production Guard и проверяет протокол, хост, метод и секреты в URL.
3. Rust проверяет HTTP-метод, URL, credential, заголовки, JSON, таймаут, proxy и TLS-настройки.
4. Переменные окружения подставляются из YAML.
5. Секреты загружаются из системного хранилища только по найденным ссылкам.
6. `reqwest` отправляет запрос через TLS-библиотеку rustls.
7. После `401` OAuth refresh выполняется один раз, затем запрос повторяется.
8. Чувствительные заголовки и известные значения секретов маскируются до возврата ответа в WebView.
9. Ответ хранится в памяти состояния React и заменяется следующим ответом.
10. Если пользователь отдельно включил историю, очищенный ответ сохраняется в локальные данные ReqVault вне workspace.

## Версионирование файлов

Каждый YAML-файл содержит `format_version: 1`. Новые поля версий 0.2–0.5 имеют безопасные значения по умолчанию, поэтому старые workspace продолжают открываться. Запрос с новым типом OAuth, multipart или GraphQL не откроется в версии 0.1.

GraphQL хранится как отдельный вариант body: query, JSON variables и operation name. HTTP-слой формирует payload непосредственно перед отправкой, поэтому YAML остаётся удобным для просмотра и diff.

## Проверки

Vitest проверяет преобразования frontend и отображение важных состояний. Rust-тесты проверяют workspace, пути, переменные, redaction, Security Lens, assertions, CLI, системное хранилище и реальную отправку запросов на локальный тестовый TCP-сервер.
