# Модель угроз

## Что защищает ReqVault

Главная цель — не допустить случайного попадания API-токенов, паролей и ключей в YAML-workspace, Git, интерфейс ответа или скопированный cURL.

ReqVault хранит в workspace только ссылки вида `{{secret:NAME}}`. Само значение сохраняется средствами операционной системы и отделяется по UUID workspace.

## Основные угрозы и меры

| Угроза | Мера |
|---|---|
| Секрет попал в Git | Значение не записывается в YAML; интерфейс предлагает ссылку на системное хранилище |
| Секрет попал в cURL | Генератор не читает значение секрета и заменяет ссылки и чувствительные поля на `***REDACTED***` |
| Сервер вернул секрет в ответе | Известные значения и чувствительные заголовки маскируются в Rust до передачи во frontend |
| Секрет попал в сообщение об ошибке | Технический текст очищается перед возвратом в WebView |
| Выход за пределы workspace через путь | Rust принимает только относительные `.yaml`-пути внутри `requests/` и `environments/` |
| Вредный HTTP-метод попал в cURL | Разрешён только фиксированный список методов |
| Передача секрета без TLS | Security Lens предупреждает об HTTP, кроме localhost и 127.0.0.1 |
| Секрет в query | Security Lens предупреждает, потому что URL может попасть в серверные и proxy-логи |
| Компрометация WebView | Включён CSP, а разрешения Tauri сокращены до необходимых |
| Credential из Postman/OpenAPI попал в workspace | Импортёр отбрасывает значения чувствительных полей и создаёт ссылки на Secret Vault |
| Подмена OAuth callback | Проверяется случайный `state`, используется PKCE S256 и callback только на 127.0.0.1 |
| Незаметное накопление production payloads | История выключена по умолчанию, включается явно и имеет лимит |
| Credential из cURL попал в workspace | Importer удаляет Authorization, cookie и пароли до записи YAML |
| Спецификация OpenAPI читает произвольный файл | Внешние `$ref` ограничены каталогом импортируемой спецификации и лимитом 10 МБ |
| Запрос ушёл на неверный production-хост | Production Guard может требовать HTTPS, ограничивать хосты и блокировать методы |
| Bundle связался со старыми секретами | При импорте создаётся новый UUID workspace, секреты и история не экспортируются |
| Секрет появился в потоковом событии | Известные значения маскируются в Rust перед передачей события во frontend |
| Поток незаметно пишет данные на диск | WebSocket/SSE-журнал ограничен памятью текущего окна и не входит в историю |
| Redirect переносит credential на другой origin | ReqVault сам обрабатывает цепочку и удаляет чувствительные заголовки при смене схемы, хоста или порта |
| Запрос обращается к localhost, private IP или cloud metadata | Production Guard блокирует loopback, private, link-local, IPv6 ULA и известные metadata endpoints; локальный хост можно разрешить явно |
| DNS-имя указывает на внутренний адрес | Перед отправкой с включённым Guard проверяется результат DNS-разрешения |
| Приватный mTLS-ключ попал в отчёт или ошибку | PEM читается только Rust-частью; содержимое ключа не передаётся в интерфейс, а runtime-ошибка сообщает только тип файла; для незашифрованного ключа показывается предупреждение |
| Секрет остался в отладочном представлении объекта | Внутренние структуры с подставленными credential не реализуют `Debug`, чувствительные `HeaderValue` помечены как sensitive, временные значения и PEM очищаются при освобождении |

## Границы защиты

ReqVault не защищает от:

- вредоносной программы или пользователя с доступом к вашей учётной записи ОС;
- компрометации самого API-сервера;
- секретов, которые пользователь вручную записал обычным текстом в YAML;
- утечки на сервере, proxy или сетевом оборудовании после отправки запроса;
- чтения обычных переменных окружения и содержимого запросов из workspace;
- захвата экрана, памяти процесса или буфера обмена сторонним ПО;
- слабого или неверно настроенного системного хранилища секретов.

Workspace не шифруется. Считайте URL, тела запросов и обычные переменные доступными любому, кто может читать папку.

## Безопасное использование

- Храните токены только через окно «Секреты».
- Не вставляйте секреты напрямую в URL, заголовки и тело.
- Не отправляйте секреты через query без необходимости.
- Используйте HTTPS для удалённых серверов.
- Включайте Production Guard для production-окружений и явно перечисляйте допустимые хосты редиректов.
- Храните mTLS-ключ вне workspace, ограничьте права на файл и не добавляйте его в Git.
- Проверяйте файлы перед коммитом и не храните в workspace реальные персональные данные.
- Блокируйте сеанс ОС и используйте шифрование диска.

## Приватность

В приложении нет аккаунта, аналитики, телеметрии и собственного облачного сервиса. Сетевой запрос уходит только на адрес, который указал пользователь. Ответ сохраняется на диск только после явного включения истории для workspace.
